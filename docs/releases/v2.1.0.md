# Pikachu Volleyball 2.1.0

Pikachu Volleyball 2.1.0 is a maintenance, packaging and architecture release focused on a leaner Linux desktop build, faster startup and clearer runtime boundaries without changing the historical game simulation.

## Highlights

- Keep Electron 35.7.5 while updating electron-builder / app-builder-lib to 26.15.7 and preserving the existing security boundary.
- Package the AppImage with Zstd-compressed SquashFS at 128 KiB blocks. The validated final candidate is approximately 92.6 MiB, about 6.9% smaller than the validated 99.44 MiB normal-compression v2.1 baseline while retaining fast real-world startup on Fedora.
- Preserve the fast-startup decision: the earlier approximately 81.8 MiB maximum/XZ candidate was rejected because it could take roughly one minute to open on real Fedora hardware.
- Enforce a fail-closed AppImage launcher policy: command-line switches that explicitly disable or relax Chromium sandbox layers are rejected, and the application refuses to launch if Chromium sandbox prerequisites are unavailable rather than silently disabling the sandbox.
- Package only the required Electron `en-US` locale and remove redundant packaged `node_modules` / Pixi copies already bundled by Webpack.
- Disable production source maps and keep the application payload inside `app.asar` limited to the production web build, desktop integration and package metadata.
- Use the CanvasRenderer path required by the game and defer the heavier PixiJS/game runtime until after the lightweight application shell is painted.
- Keep the historical 25 Hz simulation timing while exposing explicit lifecycle state IDs and a small public game-command boundary for pause state, lifecycle state and match-in-progress state.
- Add a presentation snapshot boundary so `GameView` no longer holds or mutates the live physics model while preserving the historical punch-effect sequence.
- Consolidate persisted settings, integrated-menu strings, menu styles and locale build configuration to reduce ownership drift without introducing a new localization framework.
- Preserve English, Spanish (Argentina), Catalan, Korean and Chinese production outputs, browser/PWA support and the desktop Quit path.

## Gameplay preservation

Pikachu Volleyball 2.1.0 does not intentionally change physics, AI, collisions, scoring, historical 25 Hz simulation timing, slow motion, game-state durations, practice behavior or scoring semantics.

Player control remapping, match settings, audio, graphics, interface theme, language switching, Restart, quick rematch and desktop Quit continue through the integrated menu.

## Linux packaging and startup

The final Linux package uses:

- Electron 35.7.5
- electron-builder / app-builder-lib 26.15.7
- AppImage x86_64
- Zstd SquashFS compression
- 128 KiB SquashFS blocks
- only `en-US.pak` from the Electron locale set
- no runtime `node_modules` inside `app.asar`
- fail-closed Chromium sandbox enforcement

GitHub Actions startup measurements are retained for regression comparison, but real Fedora AppImage startup is the release authority. The Zstd candidate was manually validated on Fedora with normal fast startup and normal gameplay/menu behavior.

## Download and verification

The GitHub release will provide:

```text
Pikachu-Volleyball-2.1.0-x86_64.AppImage
SHA256SUMS.txt
```

Verify the downloaded AppImage from the same directory:

```bash
sha256sum -c SHA256SUMS.txt
chmod +x Pikachu-Volleyball-2.1.0-x86_64.AppImage
./Pikachu-Volleyball-2.1.0-x86_64.AppImage
```
