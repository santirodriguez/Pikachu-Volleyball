# Pikachu Volleyball 2.1 Preservation Baseline

This document is the active regression baseline for continued 2.1 development. It records current accepted behavior that may be reorganized internally but must remain available unless a later task explicitly changes the requirement with sufficient regression evidence.

The historical `docs/2.0-preservation-matrix.md` remains a record of the 2.0 development cycle and is not the active authority for 2.1 work.

## Preservation matrix

| Area | Current behavior to preserve | Validation |
|---|---|---|
| Physics | Existing collision, movement, ball, net, ground and scoring calculations | Deterministic tests where practical; manual match checks |
| AI | Existing computer-player behavior, side selection and AI-vs-AI inactivity flow | Deterministic scenarios where practical; manual matches |
| Timing | 25 FPS default, 5 FPS slow motion, current frame-count transitions and gameplay rhythm | Controller characterization plus manual play |
| Game flow | Intro, original mode selection, match start, rounds, scoring, match end and return flow | Controller characterization plus web/Electron smoke |
| Default controls | Player 1: D/G movement, R up, V down, F down-right, Z or Left Shift Power Hit. Player 2: arrows, Enter or Left Control Power Hit | Existing input/control tests plus manual keyboard check |
| Fixed global controls | P opens/closes the pause menu, Escape is menu back/cancel, B is practice ball reset | Input/menu characterization and smoke |
| Quick rematch | Power Hit starts a fresh match after the existing game-end delay and the hint becomes visible at the current boundary | Controller characterization and completed-match smoke |
| Practice mode | Runtime-only practice mode hides scoreboards and prevents normal scoring | Controller/settings characterization and manual check |
| Practice reset | B resets the ball only during an active practice round | Controller/input characterization |
| Graphics | Sharp and soft rendering choices and persistence | Settings tests and visual check |
| BGM | On/off behavior and persistence; non-critical warm-up remains deferred | Settings/audio smoke and startup measurements |

## Controller characterization targets

Before Phase 3 moves controller ownership boundaries, add behavior-focused characterization for these flows without rewriting the state machine:

1. intro skip and automatic intro completion;
2. original mode selection, including one-player side selection;
3. inactivity transition to AI-versus-AI;
4. pause and resume without advancing game state;
5. restart returning to the intro with input immediately usable;
6. practice-mode B reset and its practice/round guard;
7. scoring on each side, round-end slow motion and next-round transition;
8. winning-score boundary and game-end transition;
9. quick-rematch availability at the existing frame boundary;
10. automatic return to intro after the existing game-end duration;
11. critical frame totals that define the current intro, selection, match-start, round and game-end rhythm.

Tests should assert externally meaningful state and collaborator behavior rather than private implementation trivia. Existing deterministic RNG support may be used where needed.

## Review rule

Every implementation pull request targeting `v2.1` must identify the preservation areas it affects and how those areas were validated. No task receives implicit authority to change physics, AI, scoring rules, collision equations or timing values.
