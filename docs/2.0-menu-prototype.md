# Pikachu Volleyball 2.0 Menu Prototype

## Purpose

This branch contains a visual and interaction prototype for the future integrated pause menu. It does not replace the current production menu and does not change gameplay settings.

## Preview

Run the development server:

```bash
npm start
```

Open:

```text
http://localhost:8080/en/?menuPrototype=1
```

Desktop-only items can be previewed with:

```text
http://localhost:8080/en/?menuPrototype=1&desktop=1
```

The regular application remains unchanged when `menuPrototype=1` is absent.

## Controls

- Up and Down: move through menu items.
- Z, Left Control or Enter: select the highlighted item.
- Escape: close or reopen the prototype.
- Mouse: hover and click menu items.
- Prototype setting rows can be clicked to cycle their displayed values.

Menu input is intercepted while the prototype is open so it does not reach the game underneath.

## Visual direction

The design intentionally combines a modern information hierarchy with the visual language of the original game:

- sky blue, court yellow and court red accents;
- dark blue structural panels derived from the game screen contrast;
- square, pixel-aligned borders instead of generic rounded cards;
- hard offset shadows rather than glass or floating material effects;
- compact typography and strong selection feedback;
- the existing Pikachu application icon and existing navigation sounds;
- restrained motion and a reduced-motion fallback.

The design avoids unrelated icon sets, external artwork, glassmorphism, heavy blur and generic desktop dropdown styling.

## Prototype scope

Included:

- primary menu hierarchy;
- selected and unselected states;
- match settings preview;
- controls preview including `ControlLeft`;
- audio and graphics preview;
- language preview including a long Catalan layout sample;
- keyboard, mouse and basic accessible dialog behavior;
- desktop-only Quit visibility.

Not included:

- actual pause state integration;
- real restart, settings, language or quit commands;
- production translations;
- removal of the existing toolbar or Electron command bridge outside prototype mode;
- final visual approval.

## Approval gate

Full menu integration must not begin until the prototype has been reviewed for:

- coherence with the game;
- color and contrast;
- layout density;
- menu hierarchy;
- keyboard feel;
- long-label handling;
- web and desktop suitability.
